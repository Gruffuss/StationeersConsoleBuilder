# M1 report: the editor core

Measured on 2026-10-05 at commit `083fea8` (branch `m1-editor-core`; the drag's cache-miss series a little later, on the same core and runtime code), with Lua-CSharp pinned at `d9fb336` and the vector mod at `9b126ca` (v0.11.72). The work followed the M1 plan; M0's report is `docs/spike-m0.md`.

## Verdict: delivered; the comparison is partial and found a colour gap

Every item of the roadmap row is in place: "Project model; `src` printer/parser with round-trip tests over examples 01–15; CodeMirror code pane; canvas preview of raw shapes from the real core; TagNodes selection and handles; element rects honoured; binary frame transfer".

| `src` printer and parser, round trip over examples 01–15 | yes | `web/src/srctext/`. Suites at the end of M1: `core/Core.Tests` 252 checks, `ALL PASS`; `npm test` 316 tests in 21 files; `npm run build` clean.

What the verdict does not cover:
- **The comparison is partial.** The captures of examples 01–07 are blank because of a capture defect, not a renderer or preview problem. The owner ran 01–07 on a console and they render correctly, and upstream has reproduced the fault: a scene with no `T` node captures blank. Those seven could not be compared at M1. Upstream has since fixed the capture path in 0.11.83 and re-captured all 18 examples; the comparison against them belongs to M2's re-pin (finding 2).
- **The preview differs from the game in examples 10 and 12.** Data declared once with `keep = 1` reads `--` on the live console too, while the preview shows the declared values. Upstream has measured the cause: upserts of one id with no `ui:commit()` between them merge into one, with `data` replaced whole, and the fake host does not model that (finding 3, a known limit carried to M3). Upstream has fixed both examples after 0.11.81, so M2's re-pin picks them up.
- **"core ready" is slower than M0's 104 ms:** 392 ms on page load in the dev server with a warm cache. A worker boots in about 50 ms on its own, so the rest is time spent while the app itself loads (see Load).

The comparison also found a gap that is not on the M1 list: **the game composites through an 8-bit linear buffer, the preview in sRGB**. The vector mod's `REFERENCE.md` documents all three effects at the pin:
- translucent colours blend in linear light (line 1032), so faded fills, halos, glows, fades and anti-aliased edges come out darker in the preview;
- two-stop gradient ramps are lighter mid-ramp (lines 1390–1394);
- dark flat colours lose levels (lines 321–334): below about (20, 20, 20) they crush together and come out lighter.

Opaque mid and bright flat colours match. The fix is a renderer change, carried to M2 (finding 1).

## Measurements

The machine is an AMD Ryzen 9 9950X3D (16 cores, 32 threads) on Windows 11 Pro 10.0.26200, with .NET SDK 10.0.401 and Node 24.19. The browser is the Chromium 152.0.7977.130 in the desktop browser pane (M0 used Chrome 154). Everything ran on localhost against the Vite dev server unless stated, with no throttling set. The browser pane paced animation frames at about 23 per second during the frame series. A round trip is timed per request, so the pacing does not change it.

Every measurement ran in the dev "Example scripts" mode, so each example runs as its own Lua with its own data and tick. With "Compare" on, the canvas is 460 × 460 canvas pixels (the drawing buffer; zoom 1, `devicePixelRatio` ignored).

### Drag: patch round trip

`bridge.patchMs` for example 08's structure element `console_s`, patched with its printed `src` (the Task 7 snapshot `web/test/fixtures/examples/08-console.console_s.src`, 3,832 characters), one patch every 60 ms.

**As a drag does it:** every patch differs from the one before. Each patch moves the first tank's `R` by 0.01 in `x`, so the mod's `SceneText` cache (32 texts, keyed by the exact text) misses and the scene is parsed again every time.

| cache miss (the drag figure) | n | median | p95 | min / max |
|---|---:|---:|---:|---:|
| first 25 after the load | 25 | 4.5 ms | 9.7 ms | 1.9 / 10.9 ms |
| next 100 | 100 | **2.1 ms** | 4.1 ms | 1.4 / 8.4 ms |
| a second 100 | 100 | 1.7 ms | 2.9 ms | 1.3 / 6.5 ms |

**The cache-hit floor:** the same printed text every time, so `SceneText.ToProps` returns its cached parse.

| cache hit (floor) | n | median | p95 | min / max |
|---|---:|---:|---:|---:|
| 100, between the two miss series above | 100 | 1.3 ms | 2.6 ms | 0.9 / 4.7 ms |
| 100, in an earlier session, after 25 warm-up patches | 100 | 1.6 ms | 4.8 ms | 1.0 / 6.7 ms |

A drag sends at most one patch per animation frame, and no frame is requested while a patch is in flight. On a scene this size a drag's patch costs about 2 ms at the median; the re-parse adds 0.4 to 0.8 ms of that over the cache hit.

## Comparison with console captures

The captures are 460 × 460 PNGs of a 1 × 1 console running vector 0.11.72 (`9b126ca`), the same commit as the pin; the game's capture dumps confirm that build. They are not in this repo.

The tool is the "Compare" toggle of the dev "Example scripts" mode (`web/src/editor/CaptureOverlay.tsx`). To use it:
1. Pick a PNG; it never leaves the browser.
2. The PNG lies over the canvas at the surface size, with an opacity slider and a difference blend.
3. "Measure" reads the WebGL pixels and the PNG's pixels and shows `diffPercent` at tolerance 4 (out of 255), with the differing pixels in red.

A PNG that is not exactly the surface's size is refused with a message rather than resampled. Running another example clears the last result.

What `diffPercent` compares:
- It counts a pixel when its largest colour channel differs by more than the tolerance (`web/src/editor/diff.ts`).
- Alpha is not compared. A capture's alpha is its render texture's: blending leaves it below 255 under translucent shapes, while the preview's is always 255.
- Text is DOM over the canvas, so "Measure" sees shapes only. Every label in a capture therefore counts.

A capture is never pixel-identical. The dither noise is ±2/255, text is TextMeshPro, and the composite is linear into 8 bits. Read the share as a pointer to where to look.

The tool cannot separate causes. Where an example animates or ticks data, a pixel can differ by its phase and by compositing at once. The table therefore names a cause as measured only where pixels were sampled and checked against the arithmetic, and marks every other attribution as a hypothesis.

### Findings

1. **Opacity composites in linear light; gradient and dark-colour transport changed in v0.11.118.** The original M1 capture established linear opacity blending and the old 8-bit linear vertex-colour loss. Those captures remain historical measurements; they do not describe the current vector colour path.
   - Vector RGB now travels as float straight sRGB in UV2, interpolates there and decodes per fragment. The reported midpoint of #5FD9A8 → #2E8B6E is (70.6, 177.9, 138.9), within a byte of CSS (70, 178, 139), replacing (75, 183, 142).
   - Opaque vector #050505, #0A0A0A and #141414 now read 5, 10 and 20. Native UI and picture tint keep the byte-linear path; an older or missing game shader bundle keeps the old vector path too.
   - Preview scene and cover targets are WebGL 2 SRGB8_ALPHA8. Destination reads decode for linear blending; writes encode after blending. The display pass samples linear values and encodes once. Linear opacity blending remains: the undithered 14-ztext shutter model gives (210, 80, 57), within one byte of its historical capture (211, 80, 58).
   - The CSS importer preserves authored stops; it adds no intermediate stops to compensate a linear ramp. E1's gradient switch still crossfades two layers, through opacity blending, without interpolating gradient identifiers.
   - DOM labels under translucent covers still composite through the browser in sRGB. Browser observation and a new in-game capture of dark flats, ramps and overlaps belong to the owner; offline numeric and shader tests are not captures.
2. **Captures 01–07 show no vector layer, because of a capture defect.** All seven files are byte-identical: the `bg` panel's colour with the console frame.
   - The owner ran 01–07 on a console and they render correctly, so this is not a renderer or preview problem.
   - Upstream has reproduced the fault: a scene with no `T` node captures blank, and adding one `T` fixes it. None of 01–07 has a `T`; every example from 08 on has one.
   - The cause, found upstream after M1: the dither shader carries coverage in `TEXCOORD1`. The capture renders a clone of the tree on a canvas of its own, and that canvas did not enable the TexCoord1 shader channel, so coverage reached the shader as 0 and the vector layer drew fully transparent. A TextMeshPro label enables that channel, which is why any scene with a `T` captured correctly. Live consoles were never affected. This is fixed in vector 0.11.83, with new captures of all 18 examples; comparing against them is M2 work, with the re-pin. Any canvas that draws vector geometry needs the TexCoord1 channel.
3. **Data declared once with `keep = 1` reads `--` on the console, while the preview shows the declared values.**
   - In 10, `$long` reads `--`; in 12, `$names[i]` and `$picked` do. Each is sent once in the data element's declaration and never resent.
   - The game's own capture dumps show that the live console read `--` too, so the captures are faithful here. The preview shows the declared values, as the examples' own comments promise.
   - The rule, as upstream has measured it: upserts of the same id with no `ui:commit()` between them merge into one before the mod is called. The last writer of each prop wins, `data` is replaced whole, and `keep` is not dropped. A commit between them makes two upserts.
   - 10 and 12 never call `ui:commit()` between declaring the data element and their first tick's `set_props({ data = … })`, so the tick's `data` replaces the declared one. (08, for one, commits right after its declaration.)
   - Upstream has fixed examples 10 and 12 after 0.11.81, so M2's re-pin picks up the fixed scripts.
   - The fake host does not model that flush and merge of an element declared and then `set_props`'d before a commit. This is a preview fidelity gap, carried as a known limit (M3).

## Known limits carried forward

### M2: fidelity, faces and the property panel

- **Compositing in linear light** (finding 1). The renderer blends in sRGB, so it gets three things wrong: translucent blending, gradient ramps between vertices, and dark flat colours below about (20, 20, 20).
- **Text is always on top.** Labels are a DOM layer over the canvas, so `ztext` interleaving (a later shape covering a label) is not drawn. That needs text in WebGL.
- **No game faces.** Labels use `"Liberation Sans", Arial, Helvetica, sans-serif` (`web/src/editor/text.ts`; Liberation Sans is the game's default face, and Arial has the same metrics), not TextMeshPro, so glyph shapes, kerning and rich-text effects differ.
- **No `IMG`.** Images go through the mod's test stub and draw nothing. None of the 15 examples draws one.
- **No native elements.** `panel`, `label` and the other ScriptedScreens elements are not drawn. Every example's backdrop is a `panel`, and 13's title is a `label`. The surface background is a fixed `#0A121C` until it has its own ruling.
- **Text-node fallback.** The pin's text placements carry no node, so each label is paired with its `T` by the vertex where the `T` would start (`ShapeStart`). In three cases a label gets the wrong node or none (−1), and a label with none cannot be clicked:
  - a skipped `T` inside a run of consecutive `T`s;
  - two consecutive `T`s inside a concave clip;
  - a `T` inside a refining masked group.
- **Stale spans under refining masks.** At v0.11.72, the node spans of a refining masked group's children are recorded before the refine moves the cuts. Click-select inside such a group can pick the wrong child or none (example 15's mask).
- **Selection gaps.** Hidden, invisible, clipped-away and `IMG` nodes, and a `T` with no span, cannot be clicked; select them in the code pane. Other gaps:
  - a stroke-only shape is not picked by its interior;
  - a path's box ignores arc bulges;
  - a sheared `T` shows its label box, not the sheared outline.
- **Invalid pane text is not kept.** While the code pane holds text the parser rejects, the canvas keeps the last good model. The text itself is discarded on a page switch, on an outside change of the scene (undo, for one), and on a canvas drag.
- **Element placement** relative to `parent_id`, and z order within a parent, are not modelled.
- **The dev-only example fixtures ship in the bundle.** The example picker's structure-only fixtures are part of the production bundle; M4's templates replace them.
- **Validation on the UI thread.** validateScene runs on the UI thread; crafted scenes are bounded by work budgets, not by a timeout (M2 moves it into a worker).

### M3: play mode and the full host

- **No pointer input.** `hover` and `down` never fire, and `SC` regions do not scroll (M1 ruling 3). Example 09 shows its list at the top, and 12 cannot be clicked.
- **A partial `ss.ui`.** The fake host covers `ss.ui.surface(name)` and `ss.ui.activate(name)`; on a surface, `clear`, `commit`, `set_resolution`, `size`, `element` and `get`; and a handle's `set_props`. Where it differs from the game: `surface()` and `activate()` without a name throw (the game uses `"main"`); `get` of an unknown id returns nil (the game throws); there is no `remove`, `set_style`, `on` or `off`; an empty id is accepted (the game throws); and `set_resolution` is ignored, so `ui:size()` and fraction rects never see a virtual resolution.
- **No flush before a commit** (finding 3). In the game, upserts of one id with no `ui:commit()` between them merge into one: the last writer of each prop wins and `data` is replaced whole, so an element declared and then `set_props`'d before a commit loses its declared data. The fake host instead hands every declaration and every `set_props` to the mod as an upsert of its own (its `commit` does nothing), so under `keep = 1` the declared data survives: for examples 10 and 12 at the pin, the preview shows values that a console shows as `--`. The fake host should model ScriptedScreens' flush and merge, and codegen must commit after declaring data elements.

### Keeping in step with the pin

- **Ported mod code must follow the pin.** `core/Core/LiveScene.cs` (from `VectorGraphic.cs`) and `core/Core/VectorHost.cs` (from `VectorElementPatch.cs`) are ports at v0.11.72. Each header names its line ranges. Re-port both on every re-pin. Upstream 0.11.74–0.11.77 already change behaviour they cover: for one, a structure upsert with an identical `src` becomes a no-op.
- **The colour leniency between 0.11.64 and the pin.** The preview runs v0.11.72, which trims every colour and accepts `gray`; the export minimum is 0.11.64, which does neither. `validateScene` warns on both, so builder output does not rely on them, but hand-written custom Lua can still pass in the preview and draw magenta on a 0.11.64 console.

### M5: adopting existing scripts

- **The TS parser is stricter than the mod** (M1 ruling 9). It rejects what the mod hangs on and what the mod silently truncates. It also rejects:
  - `NaN`, `Infinity` and values beyond float32;
  - whitespace other than spaces inside a line;
  - an empty quoted key;
  - `c` or `op` as a `SCENE` key.

  An adopt-mode import of a hand-written script will need to report these clearly, or offer a lenient path that never reaches the core.

## How to run it

You need the .NET SDK 10.0.401 or newer, and Node 24 with npm.

```sh
git clone --recurse-submodules <this repo>    # Windows: git -c core.longpaths=true clone --recurse-submodules ...
cd <repo>                                     # an existing clone: git submodule update --init
dotnet workload install wasm-tools wasm-experimental
dotnet run --project core/Core.Tests -p:VectorSrc=<abs path to core/vendor/vector/>     # ends with ALL PASS
rm -rf core/Wasm/bin/publish                  # publish into an empty folder
dotnet publish core/Wasm -c Release -p:VectorSrc=<abs path to core/vendor/vector/> -o core/Wasm/bin/publish
cd web
npm install
npm run precore                               # copies _framework and the vector examples into web/public
npm test
npm run dev                                   # then open the printed localhost URL
```

These steps were checked from a fresh clone of the branch (at `fa45b48`) for this report: the suite printed `ALL PASS`, the publish succeeded, `precore` copied the 20 `_framework` files and the 15 example scripts, `npm test` passed 297 tests, and `npm run build` succeeded.

Notes:
- Always pass `-p:VectorSrc` with the absolute path of the `core/vendor/vector/` submodule, ending in a slash, so a local `core/VectorSrc.user.props` never decides what is built.
- After any change under `core/`, publish into an emptied folder and run `npm run precore` again.

To compare with a capture:
1. Tick "Example scripts (dev)" and pick an example.
2. Tick "Compare", choose the capture PNG, and press "Measure".
