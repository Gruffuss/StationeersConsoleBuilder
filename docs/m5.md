**Status: implementation integrated on `m5-imports`; offline, browser and in-game evidence recorded below.** Merging into `main` waits for the owner's go; the vector
re-pin is the last step before the public deployment (owner, 2026-10-12), not a condition of that merge.

This report covers `m5-imports` at `0512213` and the M5 plan (Tasks
1–10 built, Task 11 here). Vector stays pinned to **0.11.112** (`24409df`); Lua-CSharp stays `d9fb336`. The builder
version stays **0.4.0**; project, transfer codec and runtime library versions stay **1** (an imported theme is an
optional `themes` field that older builds ignore).

## Owner decisions applied

- **OQ1 (c):** an imported theme lives in the project that uses it (JSON, share links and the export's embedded block
  reopen with the same look) and in a per-browser library for reuse in other projects.
- **OQ2 (b):** adopting a script keeps its artwork (pages, captured values as preview samples, click ids); its Lua is
  kept verbatim in the custom block as a long comment that never runs; the player keeps the original file.
- **OQ3 (a):** the owner's Vanilla + `tokens.json` and `components/bundle.css` are the importer's test fixture,
  committed unchanged.
- **Editor UI (2026-10-12):** modal dialogs are allowed. The M5 panels stay non-modal prototypes, built as
  self-contained components (props and callbacks in, no layout or container assumptions, one mount each) so the UI
  redesign can host them in dialogs unchanged.

## Departures from the plan

- **Task 2:** runtime project themes stay `Theme` objects while serialized entries are theme-file envelopes; a
  malformed browser-library key that the sanitizer would rename is skipped with a note, so every listed theme stays
  removable by its stored key.
- **Task 4:** `proposeTheme` takes an optional snapshot of this browser's local faces so it stays pure. Type rules match
  a style by its own name only (synonyms match the design system's style names, not CSS classes); a bar's fill is the
  track's child whatever its element; border and outline longhands and implicit `currentcolor` are reported as
  unrepresented instead of dropped; a role whose name a design-system token also uses keeps both, renamed and reported.
- **Task 5:** the link route refuses redirects (the player never gave that URL) and reports it; a host's HTML answer for
  an optional file becomes a note while `tokens.json` stays read; dropped files the importer never reads are skipped
  with a note before their bytes are read; an imported theme gets a display name distinct from the provided themes;
  only the type faces the mapping needs, at the weights they serve, are imported into this browser, and a face the
  player already has locally is kept with a note; widget defaults keep only the parameters the player set and never a
  project's page ids; Stop, Clear files and a selectable prompt fallback were added.
- **Task 7:** no `fromProps` option was needed — the table reader already writes a root style map and bare root paint
  keys onto the header; the offer says the script has no embedded builder project (an embedding-off builder export
  takes the same route); native-only screens get pages; label text that looks like a binding or a placeholder becomes
  an unbound preview sample so it prints literally; the exporter's Lua lexer tells an active custom-block end marker
  from one inside the retained comment; adopted builder pages are named by their surface; the report survives
  drags and edits until dismissed or the project is replaced (not a page reload).
- **Task 9:** the Load pictures action and every picture note live in one component beside the page shape; a click
  loads only that page's currently pending remote pictures (no standing permission); a core replacement may repeat an
  interrupted decode from local or already-fetched bytes but never repeats a network request; an HTTP error status is
  reported as such, not as a CORS refusal; a picture over the browser's maximum texture size is named in a note.
- **Editor (found by the browser walk, pre-existing since M4's integration):** the export controls unmounted during a
  drag, so the header shrank, the canvas moved under the pointer and every drag landed off by that distance. The
  chrome now stays mounted through gestures, and every gesture keeps the canvas origin and view of its press.
